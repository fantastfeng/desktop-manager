# 离线桌面管理工具设计文档

日期：2026-05-20
目标平台：Windows
项目根目录：E:\桌面管理

## 目标

构建一个小巧的离线 Windows 桌面管理应用，用来保持桌面干净，同时保留快捷方式的快速访问能力，并提供本地便签功能。

第一版聚焦一个实用的极简 MVP：

- 快捷方式收纳
- 快捷方式搜索与启动
- 桌面清理与恢复
- 本地便签
- 主管理窗口 + 独立便签窗口

应用必须完全离线运行，不需要登录、云同步、网络访问或任何外部服务。

## 技术栈

使用：

- Tauri：桌面应用壳与多窗口支持
- React：用户界面
- TypeScript：前端代码
- Rust：本地文件操作、快捷方式处理、Tauri 命令
- SQLite：本地数据持久化

这个技术栈适合本项目，因为应用目标是小巧、快速、本地优先，并且第一版只面向 Windows。

## 产品范围

### 第一版包含

- 扫描 Windows 桌面快捷方式
- 将选中的桌面快捷方式移动到本地托管目录
- 在主窗口中显示已收纳的快捷方式
- 按名称搜索快捷方式
- 从应用内启动快捷方式
- 将已收纳快捷方式恢复到原桌面路径
- 创建本地便签
- 编辑便签标题、内容、颜色、位置和尺寸
- 每张便签可作为独立窗口打开
- 应用重新启动后恢复便签窗口
- 所有数据只保存在本地

### 第一版不包含

- 联网功能
- 登录或账号系统
- 云同步
- AI 分类
- 托盘常驻
- 全局快捷键
- 自动分类规则
- 插件系统
- 多平台支持
- 复杂主题系统

## 应用结构

### 主窗口

主窗口是应用的控制中心，包含两个主要区域：

1. 快捷方式管理
2. 便签管理

快捷方式管理区域支持扫描、收纳、搜索、启动和恢复快捷方式。

便签管理区域支持创建、打开、编辑和删除便签。

### 便签窗口

每张便签打开为一个独立的 Tauri 窗口。便签窗口支持：

- 编辑标题和内容
- 移动窗口
- 调整窗口大小
- 修改便签颜色
- 关闭窗口但不删除便签
- 保存窗口位置和尺寸

关闭便签窗口只表示隐藏或关闭该窗口，不会删除便签数据。

## 本地存储

应用数据存放在：

```text
%LOCALAPPDATA%\OfflineDesktopManager
```

已收纳快捷方式存放在：

```text
%LOCALAPPDATA%\OfflineDesktopManager\Shortcuts
```

SQLite 数据库存放在：

```text
%LOCALAPPDATA%\OfflineDesktopManager\data.db
```

## 数据库设计

### shortcuts 表

```text
id              TEXT PRIMARY KEY
name            TEXT NOT NULL
original_path   TEXT NOT NULL
managed_path    TEXT NOT NULL
target_path     TEXT
icon_path       TEXT
last_opened_at  TEXT
created_at      TEXT NOT NULL
```

`original_path` 记录快捷方式原本所在位置。`managed_path` 记录应用收纳后的文件位置。恢复快捷方式时使用这两个路径。

### notes 表

```text
id          TEXT PRIMARY KEY
title       TEXT NOT NULL
content     TEXT NOT NULL
color       TEXT NOT NULL
x           INTEGER
y           INTEGER
width       INTEGER NOT NULL
height      INTEGER NOT NULL
is_open     INTEGER NOT NULL
updated_at  TEXT NOT NULL
```

当便签从未打开，或系统无法提供可靠窗口坐标时，窗口位置可以为空。

## 快捷方式流程

### 扫描

应用扫描当前用户的桌面目录，查找 `.lnk` 文件，并在主窗口中展示扫描结果。

### 收纳

当用户收纳快捷方式时，Rust 后端将 `.lnk` 文件从桌面移动到应用的快捷方式托管目录，并创建或更新数据库记录。

如果托管目录中已经存在同名文件，应用应生成唯一文件名，同时保留原始路径记录。

### 启动

启动快捷方式时，应用通过操作系统打开托管目录中的 `.lnk` 文件。启动成功后，更新 `last_opened_at`。

### 恢复

恢复快捷方式时，应用将 `.lnk` 文件从托管目录移动回 `original_path`。

如果原始路径已经存在文件，应用不能覆盖，应显示明确的冲突提示。

## 便签流程

### 创建

创建便签时，应用向 SQLite 插入一条记录，并打开一个默认尺寸和默认颜色的便签窗口。

### 编辑

便签编辑内容保存在本地。为了避免频繁写入，前端可以对内容更新做防抖处理后再发送给 Rust 后端。

### 关闭

关闭便签窗口时，应用更新 `is_open`，并在可用时保存最新的位置和尺寸。

### 重新打开

用户从主窗口打开便签时，应用创建或聚焦对应的便签窗口。

## 错误处理

应用需要为以下情况显示简洁明确的错误信息：

- 找不到桌面目录
- 快捷方式移动失败
- 快捷方式恢复时发生路径冲突
- 快捷方式启动失败
- 数据库打开或迁移失败
- 便签窗口创建失败

应用绝不能静默删除快捷方式或便签。
